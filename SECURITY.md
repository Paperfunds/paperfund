# Security policy

Do not post credentials, private user records, custody paths, signing material or exploitable financial details in public issues. Use the repository's **Security → Report a vulnerability** feature when enabled. If unavailable, arrange a private reporting channel with the repository owner before sending sensitive details. No public contact address or response SLA is asserted here.

Include the affected commit, impact and reproduction with synthetic data. Do not test against production accounts, move funds, alter financial STOP or access signing material. Historical test keys must never be used for custody. The software license does not authorize access to production infrastructure.
